# 奶龙自动 Python 代码评测与傲娇报告设计

日期：2026-08-09  
状态：已实施，code review 通过

## 目标

当用户明确授权自动代码评测，并且桌面活动被高置信识别为正在编码时，后台从明确的代码根目录发现刚保存的 Python 文件，提交一次受控的 Python 静态评测任务；任务完成后由奶龙通过现有气泡通道输出简短、中度傲娇的评测摘要。

该功能不是每个桌面事件都调用 LLM，也不默认读取或持久化源代码。

## 当前边界

- 桌面采集器继续只产生脱敏的 `ActivityEvent`，不把源代码、剪贴板、截图、完整窗口标题写入事件或数据库。
- 自动评测必须由用户在设置中单独授权，默认关闭；暂停监听、免打扰、敏感窗口和全屏门禁优先级更高。
- 评测器复用现有本地代码评测服务和 DeepSeek Provider，不复用重构专用 Prompt。
- 渲染层只接收评测结果，不直接调用 LLM。
- 仅支持保存后的 Python 文件；桌宠默认使用启动目录作为代码根目录，也可通过 `NAILONG_PYTHON_REVIEW_ROOTS` 指定多个根目录。无法安全取得当前编辑内容时不触发任务。

## 触发规则

1. `ActivityEvent.application_id` 为 `code` 或 `ide`，活动类型为 `coding`，且置信度达到高置信阈值。
2. 有界文件适配器在内存中取得编码状态下刚保存的 Python 文件内容，并通过敏感文件名和敏感字面量门禁；不得从窗口标题推断或拼接源码。
3. 同一文件内容指纹在时间窗口内只提交一次；默认冷却 10 分钟，每日最多 3 次。
4. 用户主动暂停、免打扰、会议/密码框/Token 等敏感状态，或没有明确授权时，保持静默。
5. 后台队列已有任务、评测器不可用或 DeepSeek 配置缺失时，不阻塞桌宠，不重复重试刷屏。

## 数据流

```text
ActivityEvent
  -> PythonReviewTrigger（规则、授权、去重、冷却）
  -> RedactedPythonReviewRequest（内存/受控临时任务）
  -> Local Review Service / DeepSeek
  -> PythonReviewResult（问题、风险、建议、状态）
  -> PersonalityReportFormatter
  -> NotificationService
  -> Nailong bubble renderer
```

评测请求和结果只保存必要的任务元数据、内容指纹、状态和错误码。源代码不得写入活动 SQLite；临时内容在任务结束或失败后释放。日志只记录任务 ID、状态和错误码。

## 评测结果契约

结果至少包含：`task_id`、`status`、`severity`、`findings`、`suggestion`、`confidence`。`findings` 只允许结构化问题摘要，不返回完整源码或密钥内容。超时、解析失败和服务错误统一转换为可展示的失败状态。

## 人格输出

格式化器把结构化结果转换为一条 1-3 句的中文气泡：先给结论，再给最多两条关键问题，最后给一个可执行的下一步。人格为中度傲娇：使用“哼”“本龙只是顺手看看”等有限口头禅，允许轻微吐槽但不得羞辱、恐吓或掩盖严重问题。评测失败时诚实说明“本次没评完”，不得伪造通过。

## 验收标准

- 未授权、敏感窗口、免打扰或暂停时不会创建评测任务，也不会调用 DeepSeek。
- 高置信 Python 编码事件在满足冷却和预算时最多创建一个后台任务。
- 相同内容指纹在时间窗口内去重；跨文件或内容变化可重新评测。
- 评测完成后只通过 `NotificationService` 投递气泡，渲染层无 LLM 依赖。
- 任务超时、失败和 DeepSeek 不可用均有可观察状态，不影响桌宠主循环。
- 测试使用假的评测服务和假的人格格式化器，不依赖真实 DeepSeek；生产配置仍要求真实 DeepSeek。

实现入口：`src/nailong_agent/python_review.py`。设置菜单中的“自动评测已保存的 Python 代码”是独立授权开关，默认关闭。

最终验证：`622 passed, 11 skipped`；`compileall` 与 `git diff --check` 通过。

## 非目标

- 不做实时逐字符评测。
- 不默认开启截图、OCR、剪贴板或终端内容采集。
- 不改变现有主动提交代码评测的 Dashboard/API 行为。
