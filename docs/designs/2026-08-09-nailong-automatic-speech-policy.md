# 奶龙自动说话策略调整设计

日期：2026-08-09
状态：已实施，code review 通过

## 当前证据

- 运行中的奶龙、采集器和调度器均正常。
- 最近活动主要为 `other`、`browser`、`explorer`；没有 `code`、`ide` 或 `terminal` 事件，
  因此不会触发编码鼓励。
- 当前前台为 `League of Legends.exe`，窗口覆盖整个显示器。
- 全屏门禁会保留通知但不租约，避免气泡被全屏游戏覆盖；娱乐和未知状态仍保持静默。
- 普通人格冷却仍按数据库配置执行，不是进程故障。

## 目标

让用户能明确知道奶龙为什么说话或保持安静，并在用户明确选择后支持游戏场景的低打扰互动。

## 推荐策略

### 默认行为

- 编码、调试、测试失败、测试成功和长时间 idle 继续按现有人格策略工作。
- 会议、未知应用和低置信活动继续静默。
- 全屏应用继续暂缓气泡，退出全屏后再显示；不强行覆盖独占全屏，不增加音频。
- 常见游戏进程只归类为 `gaming`，不读取标题、路径或游戏内容；`gaming` 默认仍静默。

### 用户主动开启的游戏互动

- 在设置菜单增加“游戏中允许轻微吐槽”开关，默认关闭，持久化到 `pet_preferences`。
- 开启后，`gaming` 只有在连续活动窗口达到 5 分钟、冷却结束且不在免打扰时，才生成一条低优先级轻微吐槽。
- 全屏期间仍只入队不显示；退出全屏后显示，通知不会被误记为 `SHOWN`。
- 每日预算、暂停监听、免打扰、隐私授权和最小 30 秒间隔继续生效。

### 可见性和反馈

- 设置菜单增加“立即测试气泡”，只生成固定本地文案，不调用 LLM、不读桌面活动。
- 测试气泡显示后，界面和日志记录“已绘制”；全屏时明确显示“等待退出全屏”。
- 自动人格通知继续使用真实绘制 ACK，不再用“已入队”冒充用户可见。

## 安全边界

- 游戏映射只允许固定进程名白名单，例如 `LeagueClient.exe`、
  `League of Legends.exe`、`DeltaForceClient-Win64-Shipping.exe`；未知进程继续为 `other`。
- 不保存原始标题、截图、OCR、剪贴板、源代码、进程路径或游戏内容。
- 该开关只改变本地弹窗策略，不放宽 DeepSeek 远程推理授权。

## 验收

- 默认全屏游戏不弹窗、不消耗预算，退出全屏后可看到排队通知。
- 开启游戏互动且连续 5 分钟后，生成不超过每日预算的低优先级吐槽。
- 未开启时 `gaming` 永远静默。
- “立即测试气泡”在非全屏状态可见，在全屏状态保持等待并给出明确状态。
- 聚焦测试、完整 `pytest`、`compileall` 和 `git diff --check` 通过。

## 非目标

- 不增加 TTS、录音、强制置顶覆盖独占全屏或自动读取游戏聊天内容。
- 不改变现有编码/调试人格 Prompt 和 DeepSeek 脱敏边界。

## 实施结果

- `PetPreferences` 新增持久化的 `game_tease_enabled`，默认关闭；旧 SQLite 数据库启动时自动补列。
- 设置菜单新增“游戏中允许轻微吐槽”和“立即测试气泡”。测试气泡使用固定本地文案，不调用 LLM。
- 固定白名单游戏进程在隐私最小化阶段统一归类为 `game`，识别器再归类为 `gaming`，事件中不保留原始进程名。
- 连续游戏达到 5 分钟且用户已开启开关时，最多为该次连续游戏会话排队一条低优先级吐槽；离开游戏后重置，避免全屏期间重复堆积。
- 全屏门禁继续阻止通知租约，通知保持 `PENDING`，不消耗每日弹窗预算；退出全屏后再真实绘制并 ACK。
- code review 修复了渲染器协议签名遗漏、重复参数导致的编译错误，以及活动线程与调度线程共享游戏状态的并发访问。
- 验证结果：`602 passed, 11 skipped`；`compileall` 与 `git diff --check` 通过。
