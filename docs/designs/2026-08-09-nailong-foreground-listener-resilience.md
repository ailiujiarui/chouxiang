# 奶龙前台监听可靠性设计

日期：2026-08-09  
状态：已实施，code review 通过

## 当前问题

- Windows 前台钩子只在窗口发生切换时回调，桌宠启动后不会立即识别当前前台应用。
- `SetWinEventHook` 创建失败时，源线程会停止，但采集器可能仍将健康状态标记为 `listener_running=True`。
- 钩子运行中断后没有自动恢复；用户只能通过重启桌宠恢复采集。
- 不能用高频轮询替代钩子，否则会增加无意义事件和本地数据库写入。

## 方案

### 首次采样

- Windows 前台源新增 `sample_current()`，只读取一次当前前台进程和有限本地提示。
- 采集器启动成功后立即采样，仍经过现有隐私授权、敏感窗口拦截、应用规则和最小化事件流程。

### 低频看门狗

- 采集器新增独立看门狗，每 15 秒检查前台源是否仍在运行。
- 看门狗读取当前前台类别，仅当类别发生变化或钩子已停止时才进入采集流程；相同类别不重复持久化。
- 看门狗只作为丢事件和失效恢复保障，不替代 WinEventHook 的实时回调。

### 自动恢复

- 检测到源停止后，健康状态立即改为 `listener_error`。
- 每 30 秒最多尝试一次重启前台钩子，成功后更新为 `listener_running` 并执行一次当前前台采样。
- 连续失败只保留固定错误码，不保存异常文本、进程路径或窗口标题。
- 桌宠退出时先停止看门狗，再停止 WinEventHook，避免退出阶段触发重连。

## 安全与资源边界

- 不增加截图、OCR、剪贴板或键盘钩子。
- 原始进程名和临时标题仍只存在于采集调用栈中，经过 `PrivacyPolicy` 后才允许发布和持久化。
- 相同最小化应用类别不会因看门狗重复写入数据库。
- 看门狗线程使用可中断等待，停止时间不超过现有进程退出预算。

## 验收

- 桌宠启动时无需切换窗口即可产生首个最小化活动事件。
- 钩子创建失败时健康状态显示 `listener_error`，不能显示假健康。
- 钩子停止后按退避间隔自动重启，成功后恢复采集。
- 相同前台类别连续采样不增加活动事件数量。
- 完整测试、编译检查和 diff 检查通过。

## 实施结果

- 前台源新增 `sample_current()`，采集器启动后立即获取一次当前前台窗口。
- 新增 15 秒可中断看门狗，仅在前台类别变化或源停止时进入采集流程，相同类别不会重复持久化。
- Windows 前台钩子失败会更新固定错误码；看门狗每 30 秒最多尝试一次重连，成功后恢复健康状态并重新采样。
- 首次采样失败不会阻断桌宠启动，后续由看门狗负责恢复。
- 验证结果：`615 passed, 11 skipped`；`compileall` 与 `git diff --check` 通过。
