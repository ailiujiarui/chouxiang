# 奶龙设置入口与拖动交互设计

日期：2026-08-08
状态：已实施、review 通过

## 现状

- 奶龙窗口固定为 240×150，设置能力只存在于 Windows 托盘菜单，不容易发现。
- 黄色身体在鼠标按下时立即触发点击气泡，没有按下、移动、释放的拖动状态。
- 首次拒绝活动授权后，界面没有重新授权入口，奶龙会长期无法根据桌面活动响应。
- 气泡按奶龙位置创建，但窗口移动时没有显式重新定位逻辑。

## 目标

- 在奶龙身体正下方增加一个常驻“设置”按钮。
- 点击设置按钮打开紧凑菜单，不进入新的复杂页面。
- 奶龙身体支持鼠标拖动，设置按钮和设置菜单不触发拖动。
- 短按身体仍显示本地回应气泡；移动超过系统拖动阈值后只执行拖动，不再误触点击。
- 拖动期间已有气泡跟随奶龙，窗口不会被拖出当前屏幕可用区域。

## 设置菜单

设置按钮复用现有持久化和托盘控制路径，菜单包含：

1. `活动陪伴授权`：打开现有隐私授权对话框，可重新允许或拒绝本地活动采集，
   并可独立选择是否允许向 DeepSeek 发送脱敏摘要。
2. `暂停监听`：复用 `NotificationService.set_manual_pause()`，与托盘状态双向同步。
3. `全天免打扰`：复用 `NotificationService.set_do_not_disturb()`，与托盘状态双向同步。
4. `删除本地活动记录`：复用 `PrivacyStore.clear_activity_history()`，不删除授权选择。
5. `退出奶龙`：复用现有退出路径。

设置菜单不直接调用 LLM，不显示或保存 API Key、代码、窗口标题或其他原始活动内容。

## 授权更新链路

- `DesktopProcess` 向渲染器提供读取与保存 `PrivacyConsent` 的回调。
- 保存时同时更新 `PrivacyStore` 和当前 `PrivacyPolicy.consent`，现有采集器持有同一个
  policy 对象，因此无需重启即可生效。
- 拒绝授权仍保持 fail-closed；远程推理授权不能在本地活动采集关闭时单独开启。

## 窗口和拖动

- 奶龙身体保持 240×150；窗口向下增加稳定的按钮区域，设置按钮位于水平中心。
- 身体按下左键时记录全局鼠标位置和窗口起点，并切换为抓取光标。
- 移动距离达到 `QApplication.startDragDistance()` 后进入拖动；位置钳制在鼠标所在屏幕的
  `availableGeometry()` 内。
- 释放左键后恢复普通光标；未达到阈值才调用现有 `_handle_pet_click()`。
- 每次移动后重新计算所有可见气泡的位置和指针位置，不创建重复气泡或重置关闭计时器。
- 本次只保存当前进程内的位置；重启后仍从屏幕右下角开始，不新增位置持久化格式。

## 测试

- 设置按钮位于身体下方，点击时显示菜单且不触发身体点击。
- 设置菜单的暂停、免打扰、重新授权、删除记录和退出均连接既有回调。
- 重新授权写入 SQLite，并立即更新运行中的 `PrivacyPolicy`。
- 短按触发点击气泡；超过阈值的移动只拖动，不触发点击。
- 拖动位置不会越过屏幕可用边界，可见气泡跟随且计时器数量不变。
- PySide6 offscreen 测试、桌宠聚焦测试、完整测试、compileall 和 `git diff --check` 通过。

## 实施结果

- 设置按钮已位于奶龙身体下方，真实桌宠进程已重新启动并加载新窗口结构。
- 拖动、气泡跟随、短按点击区分和授权热更新均有 offscreen/单元测试覆盖。
- 完整测试：577 passed、11 skipped、1 个既有 Starlette/httpx 弃用警告。
