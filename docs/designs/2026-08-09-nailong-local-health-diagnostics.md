# 奶龙本地健康诊断设计

日期：2026-08-09  
状态：已实施，code review 通过

## 背景

桌宠当前具备活动采集、规则识别、人格决策、通知持久化和全屏投递门禁，但用户无法从界面判断“为什么没有说话”。
静默可能来自隐私未授权、监听暂停、免打扰、全屏门禁、冷却、每日预算、低置信分类或采集器没有收到事件。

## 目标

- 在本地提供一份不含原始标题、代码、截图、剪贴板、路径或密钥的健康状态。
- 让用户能在设置菜单中看到最近活动时间、最近归类、通知队列和当前静默原因。
- 诊断入口不调用 LLM、不上传数据、不改变通知策略。
- 采集器和投递器异常时给出明确的本地失败状态，而不是静默退出线程。

## 设计

### 状态模型

新增内存态 `NailongHealthSnapshot`，字段仅包含：

- `listener_running`
- `last_event_at`
- `last_application_category`
- `last_activity_type`
- `last_classification_confidence`
- `pending_count`
- `displaying_count`
- `remaining_daily_budget`
- `fullscreen_blocked`
- `silence_reason`
- `last_error_code`

时间、分类和错误码允许落本地日志；不保存原始活动内容。

### 界面

- 设置菜单新增“当前状态”入口，打开紧凑的只读诊断窗口。
- 测试气泡失败时显示结构化原因，并保留现有 tray 提示。
- 状态窗口支持一键复制脱敏诊断摘要，摘要只包含上述枚举、布尔值、计数和时间。

### 生命周期

- 活动采集器启动、停止、异常、收到事件时更新健康快照。
- 通知投递器租约、门禁阻止、绘制成功、绘制失败时更新健康快照。
- 快照只在进程内保存；“清除本地活动记录”不删除当前运行态，但会清空历史事件。

## 验收

- 全屏仍标记为“阻止普通通知”；游戏吐槽开启时显示 `game_tease_waiting` 或 `pending_delivery`，不误报为完全阻止。
- 默认游戏开关关闭时，状态显示 `game_tease_disabled`。
- 监听暂停、免打扰、冷却、预算耗尽和低置信分别可区分。
- 采集器停止或异常后能显示 `listener_stopped` / `listener_error`。
- 完整测试、编译检查和 diff 检查通过。

## 非目标

- 不增加后台常驻服务、不采集更多桌面数据、不自动上传诊断、不引入 TTS。

## 实施结果

- 新增线程安全的 `NailongHealthMonitor` 和脱敏 `NailongHealthSnapshot`，仅保存固定类别、计数、时间、布尔状态和错误码。
- 活动采集器、识别编排器、通知投递器和真实绘制 ACK 共用同一个健康监视器。
- 设置菜单和托盘菜单新增“当前状态”，支持查看并复制脱敏诊断摘要。
- 静默原因可区分监听关闭、未授权、暂停、免打扰、预算耗尽、低置信、冷却、全屏门禁、游戏开关和待投递状态。
- `PENDING` 与 `DISPLAYING` 通知计数已分离，避免把正在绘制误报为仍在排队。
- 健康监视器对应用类别、活动类型、投递结果和错误码进行二次白名单约束，防止未来调用方泄露原始内容。
- 验证结果：`613 passed, 11 skipped`；`compileall` 与 `git diff --check` 通过。
