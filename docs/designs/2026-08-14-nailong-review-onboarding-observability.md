# 奶龙自动评测授权与运行可观测性设计

日期：2026-08-14  
状态：已实施，code review 通过

## 背景

自动 Python 评测链路已经具备保存文件发现、DeepSeek 评测、去重和气泡投递能力，但用户只能从设置菜单看到一个开关，无法在开启前明确看到“保存的 Python 源码会发送给 DeepSeek”，也无法从当前状态窗口判断评测器是否已授权、最近是否触发或为什么没有触发。README 也没有说明这条链路的启用步骤。

## 目标

- 开启自动评测前给出一次明确的源码上传确认。
- 在健康诊断中显示脱敏的评测开关、最近任务状态和阻止原因。
- 在 README 中写出真实运行所需的 DeepSeek、授权和代码根目录配置。
- 增加桌宠进程级集成测试，验证设置回调和服务生命周期确实接通。

## 设计

### 授权交互

点击“自动评测已保存的 Python 代码”从关闭变为开启时，显示确认对话框，明确说明：

- 只读取启动目录或 `NAILONG_PYTHON_REVIEW_ROOTS` 下刚保存的 `.py` 文件；
- 代码会发送给配置的 DeepSeek 服务进行静态分析；
- 不会保存源码到活动数据库；
- 可随时关闭，关闭后不再创建新任务。

用户取消时，复原复选状态且不修改 SQLite 授权。关闭开关无需二次确认。

### 健康诊断扩展

`NailongHealthSnapshot` 新增以下字段：

- `python_review_enabled`
- `python_review_last_status`：`idle`、`running`、`completed`、`failed`；
- `python_review_last_error_code`：固定白名单错误码或空值；
- `python_review_silence_reason`：未授权、非编码、冷却、每日预算、免打扰或等待保存。

仅保留任务状态、时间、计数和错误码，不显示文件名、路径、指纹或评测文本。状态由自动评测服务和 `NotificationStore` 提供，不调用 LLM。

### 文档与配置

README 增加桌宠自动评测小节，说明：

1. `.env` 配置真实 `DEEPSEEK_API_KEY`；
2. 启动桌宠并完成活动采集授权；
3. 设置菜单开启自动评测并确认源码上传；
4. 默认扫描启动目录，跨项目时使用 `NAILONG_PYTHON_REVIEW_ROOTS`；
5. 未配置 Key、处于免打扰、暂停或全屏时不会弹出评测报告。

## 验收标准

- 开启开关会出现确认对话框；取消不会改变授权状态。
- 当前状态窗口能区分“未授权”“等待保存”“冷却”“评测失败”和“最近完成”。
- 诊断内容不包含源码、路径、文件名、指纹、密钥或完整评测报告。
- README 的配置和启动步骤与实际代码一致。
- 集成测试覆盖授权回调、进程启动/停止和失败状态；测试不调用真实 DeepSeek。
- 全量测试、`compileall` 和 `git diff --check` 通过。

## 非目标

- 不改变自动评测触发阈值、冷却时间、每日预算或 DeepSeek Prompt。
- 不实现编辑器插件、逐字符监听或未保存缓冲区读取。
- 不把源码、截图、剪贴板或原始窗口标题写入任何持久化表。

## 实施结果

- PySide6 开启自动评测时新增源码上传确认；取消会恢复关闭状态。
- `NailongHealthSnapshot` 增加评测授权、状态、错误码和静默原因，并对值做固定白名单过滤。
- README 已补充真实 DeepSeek、授权和代码根目录配置步骤。
- 增加桌宠进程级授权回调和健康诊断测试。
- 最终验证：`624 passed, 11 skipped`；`compileall` 与 `git diff --check` 通过。
